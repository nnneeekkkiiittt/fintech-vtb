# Конверты — backend для кейс-чемпионата ВТБ

Демо REST API для идеи «конвертов»: пользователь делит общий счёт на категории, задаёт доли пополнения, а расходы списываются из выбранного конверта.

## Технологии

- Go 1.23+
- Gin — HTTP API
- PostgreSQL + pgx — хранение данных
- SQL-миграции, встроенные в бинарник
- Docker Compose для быстрого запуска

## Запуск

Нужен Docker с Compose:

```bash
docker compose up --build
```

После старта API доступно на `http://localhost:8080`. При первом запуске создаются таблицы и три демонстрационных конверта:

| Конверт | Доля пополнения |
|---|---:|
| Рестораны | 40% |
| Такси | 25% |
| Продукты | 35% |

Проверка:

```bash
curl http://localhost:8080/api/v1/health
curl http://localhost:8080/api/v1/envelopes
```

При локальном запуске без Docker подними PostgreSQL и задай `DATABASE_URL`, затем:

```bash
go mod tidy
go run ./cmd/api
```

API сам применяет ещё не запущенные миграции при старте.

## API

Все суммы передаются в **копейках**, чтобы не использовать `float64` в денежных расчётах. Например, `250000` означает `2500,00 ₽`. В интерфейсе можно показывать рубли, конвертируя сумму при отображении.

### Конверты

| Метод | URL | Действие |
|---|---|---|
| `GET` | `/api/v1/envelopes` | Список конвертов |
| `GET` | `/api/v1/envelopes/:id` | Один конверт |
| `POST` | `/api/v1/envelopes` | Создать конверт |
| `PUT` | `/api/v1/envelopes/:id` | Изменить название и категорию |
| `DELETE` | `/api/v1/envelopes/:id` | Удалить пустой конверт без истории |
| `PUT` | `/api/v1/allocations` | Сохранить проценты всех конвертов |

Создать конверт:

```bash
curl -X POST http://localhost:8080/api/v1/envelopes \
  -H 'Content-Type: application/json' \
  -d '{"name":"Развлечения","category":"Досуг"}'
```

Изменить доли. Нужно передать каждый существующий конверт ровно один раз, а сумма процентов должна быть равна 100:

```bash
curl -X PUT http://localhost:8080/api/v1/allocations \
  -H 'Content-Type: application/json' \
  -d '{"allocations":[{"envelope_id":1,"percent":45},{"envelope_id":2,"percent":20},{"envelope_id":3,"percent":35}]}'
```

### Деньги и история операций

| Метод | URL | Действие |
|---|---|---|
| `POST` | `/api/v1/transactions/income` | Пополнить общий счёт и распределить сумму |
| `POST` | `/api/v1/transactions/expense` | Списать сумму из выбранного конверта |
| `GET` | `/api/v1/transactions` | История (`limit`, `offset`) |
| `GET` | `/api/v1/transactions/:id` | Детали одной операции |

Пополнить общий счёт на 10 000 ₽:

```bash
curl -X POST http://localhost:8080/api/v1/transactions/income \
  -H 'Content-Type: application/json' \
  -d '{"amount_kopecks":1000000,"description":"Пополнение счёта"}'
```

При долях 40/25/35 ₽10 000 распределятся как ₽4 000 в «Рестораны», ₽2 500 в «Такси» и ₽3 500 в «Продукты».

Списать 500 ₽ из конверта с `id = 1`:

```bash
curl -X POST http://localhost:8080/api/v1/transactions/expense \
  -H 'Content-Type: application/json' \
  -d '{"envelope_id":1,"amount_kopecks":50000,"description":"Ужин"}'
```

История операций намеренно не редактируется и не удаляется: это журнал финансовых действий. Для исправления операции в следующей версии можно добавить отдельную компенсирующую операцию.

## Уведомления и анкета

Код лежит отдельно от остального API — в `internal/notifications/`. Он пользуется теми же методами репозитория (`ListEnvelopes`, `CreateEnvelope`, `SetAllocations`, `ListTransactions`), собственных заглушек нет.

**Как это работает**

1. Планировщик (горутина, запускается из `cmd/api/main.go`) раз в минуту проверяет правила и создаёт уведомления:
   - приглашение пройти анкету (при первом запуске, затем через 30 дней; «Позже» откладывает напоминание на сутки);
   - в конверте закончились деньги — предложение увеличить его долю на 5 п. п. за счёт менее приоритетных конвертов;
   - новое пополнение распределено по конвертам (информационное).
2. Фронтенд забирает уведомления через `GET /api/v1/notifications` (опрос раз в 30 секунд и сразу после своих операций).
3. Анкета из 15 вопросов отправляется в `POST /api/v1/survey`. В ответ приходит уведомление-предложение: набор конвертов и доли (сумма 100%). Конверты при этом **не меняются**.
4. После подтверждения (`action: "apply"`) недостающие конверты создаются, а доли выставляются через `SetAllocations`. Существующие конверты, которых нет в предложении, сохраняют деньги, но получают долю 0%.

| Метод | URL | Действие |
|---|---|---|
| `GET` | `/api/v1/notifications` | Открытые уведомления и `unread_count` (`?unread=1` — только непрочитанные, `?refresh=1` — сначала внеплановая проверка правил) |
| `POST` | `/api/v1/notifications/:id/read` | Пометить прочитанным |
| `POST` | `/api/v1/notifications/:id/action` | Выполнить действие: `{"action":"apply" \| "boost" \| "dismiss"}` |
| `GET` | `/api/v1/survey/questions` | Вопросы анкеты |
| `POST` | `/api/v1/survey` | Ответы: `{"answers":{"1":[2],"4":[1,3],...}}` — номер вопроса → номера вариантов (с единицы) |

**Файлы**

В каталоге `NOTIFICATIONS_DATA_DIR` (по умолчанию `data/notifications`, в Docker — `/app/data/notifications` с томом `notifications_data`) лежат:

- `operations_history.json` — история изменений конвертов, сделанных через уведомления (анкета, создание конвертов, смена долей). Файл и каталог создаются автоматически, если их нет; повреждённый файл не затирается, а переименовывается в `*.corrupt-<время>`;
- `notifications_state.json` — уведомления и служебное состояние планировщика.

**Настройки (переменные окружения)**

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `NOTIFICATIONS_DATA_DIR` | `data/notifications` | Каталог для JSON-файлов |
| `NOTIFICATIONS_CHECK_INTERVAL` | `1m` | Как часто планировщик проверяет правила (`30s`, `5m`, …) |
| `NOTIFICATIONS_SURVEY_REFRESH_DAYS` | `30` | Через сколько дней предлагать пройти анкету снова |

## Основные правила

1. Проценты всех конвертов должны суммироваться ровно в 100%.
2. Пополнение распределяется методом наибольших остатков: итоговая сумма всегда совпадает с пополнением до копейки.
3. Нельзя списать больше, чем лежит в выбранном конверте.
4. Изменение баланса и запись операции вместе с деталями распределения выполняются внутри одной PostgreSQL-транзакции.
5. Нельзя удалить конверт с ненулевым остатком, историей операций или ненулевым процентом распределения.
6. Все данные пока общие для одного демонстрационного пользователя. Авторизация, привязка к реальным счетам ВТБ и интеграция с банковской инфраструктурой не входят в MVP.

## Структура проекта

```text
cmd/api/                     запуск HTTP-сервера
internal/domain/              модели, ошибки и расчёт распределения
internal/database/            запуск SQL-миграций
internal/database/migrations/ схема PostgreSQL и стартовые конверты
internal/repository/          запросы и транзакции PostgreSQL
internal/httpapi/             HTTP-эндпоинты и валидация запросов
internal/notifications/       анкета, уведомления, планировщик, история в JSON
```
